## 오늘의 기술 토픽

> **Policy as Code**

이번 밋업은 Policy as Code라는 주제를 중심으로, 조직의 보안/운영 규칙을 코드로 정의하고 자동으로 검증·강제하는 방법을 다뤘다. 쿠버네티스 환경에서 수동 리뷰 대신 Admission Controller와 정책 엔진을 활용해 배포 시점에 규칙을 강제하는 접근이 소개되었다. OPA, Kyverno 같은 정책 엔진들이 실제로 어떻게 클러스터에 적용되는지에 대한 논의가 이어졌고, 플랫폼 팀이 정책을 중앙에서 관리하면서도 개발자의 자율성을 해치지 않는 방향이 강조되었다.

## 🔑 핵심 요점

- Policy as Code는 보안·규정·운영 정책을 코드로 작성해 버전관리하고 자동 검증하는 방식이다.
- 쿠버네티스에서는 Admission Controller를 통해 리소스가 생성되기 전에 정책을 강제할 수 있다.
- OPA(Open Policy Agent)는 범용 정책 엔진으로 Rego 언어를 사용해 세밀한 규칙을 표현한다.
- Kyverno는 YAML 기반으로 정책을 작성해 쿠버네티스 네이티브 사용자에게 더 쉬운 진입점을 제공한다.
- 정책을 코드로 관리하면 수동 리뷰보다 일관되고 빠른 피드백을 받을 수 있다.
- 플랫폼 팀은 정책을 중앙화하면서도 개발자 셀프서비스를 해치지 않는 균형을 추구한다.

## 🛠 핵심 기술 쉽게 이해하기

### Policy as Code

조직이 지켜야 할 보안, 규정, 운영 규칙을 코드(주로 YAML이나 전용 언어)로 작성하고 이를 버전관리 시스템에 저장해 관리하는 방식이다. 사람이 수동으로 체크리스트를 확인하는 대신 자동화된 도구가 규칙을 검증한다.

**왜 필요한가** — 수동 리뷰는 느리고 사람마다 기준이 달라질 수 있는데, 정책을 코드로 만들면 일관되게 자동 검증할 수 있고 변경 이력도 추적 가능하다.

**발표에서는** — 밋업 전체의 핵심 주제로, 정책을 코드화하여 배포 파이프라인이나 클러스터 단계에서 자동으로 강제하는 개념이 전반적으로 소개되었다.

### Open Policy Agent (OPA)

범용 정책 엔진으로, Rego라는 전용 쿼리 언어를 사용해 다양한 시스템(쿠버네티스, API 게이트웨이, CI/CD 등)에 대한 정책을 표현할 수 있다. 쿠버네티스뿐 아니라 여러 인프라 영역에 적용 가능한 것이 특징이다.

**왜 필요한가** — 쿠버네티스에 종속되지 않고 여러 시스템에서 동일한 정책 엔진을 재사용하고 싶을 때 유용하다.

**발표에서는** — 쿠버네티스 환경에서 세밀한 정책 로직을 표현하는 대표적인 엔진으로 언급되었다.

### Kyverno

쿠버네티스 네이티브 정책 엔진으로, 별도 언어 없이 YAML로 정책을 작성할 수 있다. 리소스 검증, 변형(mutation), 생성 등을 쿠버네티스 매니페스트와 비슷한 형식으로 정의한다.

**왜 필요한가** — Rego 같은 새로운 언어를 배우지 않고도 쿠버네티스 사용자가 바로 익숙한 YAML로 정책을 작성할 수 있어 진입 장벽이 낮다.

**발표에서는** — OPA의 대안으로, 쿠버네티스 사용자 친화적인 정책 작성 도구로 소개되었다.

### Kubernetes Admission Controller

쿠버네티스 API 서버에 리소스가 생성/수정되기 전에 가로채서 검증하거나 수정하는 플러그인 메커니즘이다. 정책 엔진들은 이 메커니즘을 통해 클러스터에 통합된다.

**왜 필요한가** — 리소스가 실제로 클러스터에 반영되기 전 단계에서 정책 위반을 차단할 수 있어 사후 대응보다 효과적이다.

**발표에서는** — OPA나 Kyverno 같은 정책 엔진이 쿠버네티스에 연결되는 실제 통합 지점으로 설명되었다.

## 🧭 추구 방향과 흐름

- **Shift-left 거버넌스** — 정책 검증을 배포 이후가 아니라 배포 파이프라인이나 Admission 단계처럼 더 앞선 시점으로 옮기는 흐름이다. 이렇게 하면 문제가 프로덕션에 반영되기 전에 걸러낼 수 있다.
- **플랫폼 엔지니어링과 셀프서비스** — 플랫폼 팀이 정책을 중앙에서 관리하면서도 개발자가 직접 배포할 수 있는 자율성을 유지하는 방향이다. 정책이 가드레일 역할을 하여 통제와 자율성 사이의 균형을 맞춘다.
- **정책의 코드화와 재사용성** — 정책을 코드로 작성해 버전관리하고 테스트하며 여러 클러스터/환경에 재사용하는 흐름이 강조되었다. 이는 기존의 문서 기반 정책 관리의 한계를 극복하려는 시도다.

## 🚀 바로 활용하기

1. 로컬 쿠버네티스 클러스터(minikube, kind 등)에 Kyverno를 설치하고 기본 제공되는 샘플 정책을 적용해본다.
2. OPA 공식 문서의 Rego 튜토리얼을 따라 간단한 정책 하나를 작성해본다.
3. 쿠버네티스 공식 문서에서 Admission Controller 개념과 동작 흐름을 먼저 읽어본다.
4. 기존 조직에서 수동으로 체크하던 규칙 하나를 골라 Policy as Code로 전환하는 작은 실험을 해본다.

- [Kyverno](https://kyverno.io) — 쿠버네티스 네이티브 정책 엔진의 공식 문서와 시작 가이드를 제공한다.
