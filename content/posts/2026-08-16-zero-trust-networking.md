## 오늘의 기술 토픽

> **Zero Trust Networking**

전통적인 방화벽 중심의 경계 보안 모델은 클라우드 네이티브 환경에서 더 이상 충분하지 않다는 문제의식에서 Zero Trust Networking이 주목받고 있다. 이 접근은 네트워크 내부/외부를 신뢰하지 않고 모든 요청을 검증하는 것을 원칙으로 하며, Kubernetes 생태계에서는 Cilium, Istio 같은 서비스 메시/네트워킹 도구와 cert-manager 같은 인증서 자동화 도구가 이를 실현하는 핵심 축으로 자리잡고 있다. 이번 브리프에서는 Zero Trust의 개념과 함께 이를 실제로 구현하는 데 쓰이는 대표 기술들을 살펴본다. 각 기술이 어떤 문제를 풀고 어떻게 조합되는지 초심자 관점에서 정리했다.

## 🔑 핵심 요점

- Zero Trust Networking은 '내부망은 안전하다'는 전제를 버리고 모든 트래픽을 매번 검증하는 보안 모델이다.
- 클라우드 네이티브 환경에서는 워크로드가 동적으로 생성/삭제되기 때문에 IP 기반 방화벽 규칙만으로는 한계가 있다.
- Cilium은 eBPF 기반으로 네트워크 정책과 트래픽 가시성을 커널 레벨에서 제공해 Zero Trust 구현에 활용된다.
- Istio 같은 서비스 메시는 mTLS를 통해 서비스 간 통신을 자동으로 암호화하고 신원을 검증한다.
- cert-manager는 인증서 발급과 갱신을 자동화해 mTLS 운영 부담을 줄여준다.
- Zero Trust는 특정 제품이 아니라 아이덴티티 기반 인증, 최소 권한, 지속적 검증이라는 원칙의 조합이다.

## 🛠 핵심 기술 쉽게 이해하기

### Zero Trust Networking

네트워크 위치(내부망/외부망)에 관계없이 모든 접근 요청을 매번 인증하고 인가하는 보안 아키텍처 원칙이다. '신뢰하지 말고 항상 검증하라(Never trust, always verify)'는 슬로건으로 요약된다.

**왜 필요한가** — 클라우드와 마이크로서비스 환경에서는 경계가 모호해지고 내부 침투 시 피해가 커지기 때문에, 경계 방어만으로는 충분한 보안을 제공할 수 없다는 문제를 해결하기 위해 등장했다.

**발표에서는** — 이번 브리프의 중심 주제로, 이를 뒷받침하는 구체적인 기술들(Cilium, Istio, cert-manager)과 함께 다뤄졌다.

### Cilium

eBPF 기술을 기반으로 Kubernetes 클러스터의 네트워킹, 관찰가능성, 보안을 제공하는 CNI(Container Network Interface) 플러그인이다. 커널 레벨에서 동작해 오버헤드가 적고 세밀한 네트워크 정책 적용이 가능하다.

**왜 필요한가** — 파드 단위로 세밀한 네트워크 정책을 적용하고 트래픽을 실시간으로 가시화해 Zero Trust의 '최소 권한' 원칙을 네트워크 계층에서 구현하기 위해 사용된다.

**발표에서는** — Zero Trust를 구현하는 대표적인 네트워킹 도구로 언급되었다.

### Istio

서비스 간 통신을 제어하는 서비스 메시로, 트래픽 관리, 관찰가능성, 보안 기능을 애플리케이션 코드 수정 없이 사이드카 프록시 형태로 제공한다.

**왜 필요한가** — 서비스 간 통신에 mTLS를 자동 적용하고 세밀한 접근 제어 정책을 두어 서비스 단위의 신원 기반 신뢰를 구현하기 위해 사용된다.

**발표에서는** — mTLS 기반 서비스 간 인증을 실현하는 대표 도구로 다뤄졌다.

### cert-manager

Kubernetes 클러스터 내에서 TLS 인증서 발급과 갱신을 자동화하는 컨트롤러다. Let's Encrypt 같은 외부 CA나 내부 CA와 연동할 수 있다.

**왜 필요한가** — Zero Trust 환경에서는 서비스마다 짧은 수명의 인증서를 지속적으로 발급/교체해야 하는데, 이를 수동으로 관리하기 어렵기 때문에 자동화가 필수적이다.

**발표에서는** — mTLS 운영을 자동화하는 보조 도구로 언급되었다.

## 🧭 추구 방향과 흐름

- **경계 보안에서 아이덴티티 기반 보안으로** — IP나 네트워크 위치가 아니라 워크로드/서비스의 아이덴티티를 기준으로 신뢰를 판단하는 방향으로 이동하고 있다. Istio의 mTLS나 SPIFFE 같은 표준이 이 흐름을 뒷받침한다.
- **커널 레벨 가시성과 정책 적용** — Cilium과 같이 eBPF를 활용해 애플리케이션 변경 없이 커널 단에서 트래픽을 관찰하고 정책을 적용하는 접근이 확산되고 있다. 이는 성능 오버헤드를 줄이면서도 세밀한 제어를 가능하게 한다.
- **자동화된 인증서/신원 관리** — cert-manager처럼 인증서 발급과 갱신을 자동화하는 도구가 Zero Trust 운영의 필수 인프라로 자리잡고 있다. 수동 관리로는 짧은 수명의 다수 인증서를 감당할 수 없기 때문이다.

## 🚀 바로 활용하기

1. Kubernetes 클러스터에 Cilium을 CNI로 설치해보고 NetworkPolicy로 파드 간 트래픽을 제한해본다.
2. Istio 공식 문서의 Getting Started 가이드를 따라 mTLS가 적용된 서비스 메시를 로컬에 구성해본다.
3. cert-manager를 설치해 자체 서명 CA 또는 Let's Encrypt로 인증서 자동 발급을 테스트해본다.
4. NIST의 Zero Trust Architecture(SP 800-207) 문서를 읽고 핵심 원칙을 정리해본다.
