## 오늘의 기술 토픽

> **Internal Developer Platform (IDP)**

이 브리프는 최근 클라우드 네이티브 생태계에서 화두가 되고 있는 Internal Developer Platform(IDP) 개념을 정리한다. IDP는 개발자가 인프라 세부사항을 몰라도 셀프서비스로 애플리케이션을 배포하고 운영할 수 있도록 플랫폼 팀이 표준화된 도구와 워크플로우를 제공하는 접근 방식이다. Backstage, Crossplane, Argo CD 같은 도구들이 IDP를 구성하는 대표적인 조각으로 자주 언급되며, 각각 개발자 포털, 인프라 추상화, GitOps 배포를 담당한다. 이 문서는 관련 기술을 소개하고 학습을 시작하는 방법을 안내한다.

## 🔑 핵심 요점

- IDP는 개발자가 인프라 복잡성을 신경 쓰지 않고 셀프서비스로 배포할 수 있게 해주는 플랫폼이다.
- 플랫폼 팀은 IDP를 '제품(product)'처럼 취급하고 개발자를 그 제품의 사용자로 바라보는 관점이 중요하다.
- Backstage는 IDP의 대표적인 개발자 포털 프레임워크로, 서비스 카탈로그와 셀프서비스 템플릿을 제공한다.
- Crossplane은 쿠버네티스 API를 확장해 클라우드 인프라를 코드로 정의하고 프로비저닝하는 데 쓰인다.
- Argo CD 같은 GitOps 도구는 IDP에서 배포 자동화와 일관된 운영 상태 유지를 담당한다.
- IDP 도입의 핵심은 도구 자체보다 '골든 패스(golden path)'로 개발자 워크플로우를 단순화하는 데 있다.

## 🛠 핵심 기술 쉽게 이해하기

### Internal Developer Platform (IDP)

IDP는 조직 내부에서 개발자가 애플리케이션을 빌드, 배포, 운영하는 데 필요한 도구와 워크플로우를 하나로 묶어 제공하는 플랫폼이다. 개발자는 복잡한 인프라 설정을 직접 다루지 않고 표준화된 인터페이스(포털, CLI, API 등)를 통해 셀프서비스로 필요한 리소스를 얻는다.

**왜 필요한가** — 각 팀이 인프라를 개별적으로 학습하고 구성하는 데서 오는 중복 작업과 비일관성을 줄이고, 개발자가 비즈니스 로직에 더 집중할 수 있도록 돕기 위해 사용한다.

**발표에서는** — 오늘의 브리프에서 다루는 핵심 주제로, IDP를 구성하는 주변 기술들을 함께 소개하는 출발점으로 다뤄졌다.

### Backstage

Backstage는 Spotify에서 만들고 CNCF에 기증한 오픈소스 개발자 포털 프레임워크다. 서비스 카탈로그, 문서, 템플릿 기반의 셀프서비스 스캐폴딩 기능을 제공해 조직 내 여러 서비스와 도구를 한곳에서 탐색할 수 있게 한다.

**왜 필요한가** — 흩어져 있는 서비스 정보와 도구를 한 곳에 모아 개발자가 필요한 리소스를 빠르게 찾고 새 프로젝트를 표준화된 방식으로 시작할 수 있게 하기 위해 사용한다.

**발표에서는** — IDP를 구현할 때 가장 널리 쓰이는 개발자 포털 도구로 언급되었다.

### Crossplane

Crossplane은 쿠버네티스 컨트롤 플레인을 확장해 클라우드 인프라(데이터베이스, 스토리지, 네트워크 등)를 쿠버네티스 커스텀 리소스로 정의하고 관리할 수 있게 해주는 오픈소스 프로젝트다.

**왜 필요한가** — 인프라 프로비저닝을 코드로 선언하고, 애플리케이션 배포와 동일한 쿠버네티스 API 체계 안에서 관리하기 위해 사용한다.

**발표에서는** — IDP에서 인프라 추상화 계층을 담당하는 대표 기술로 소개되었다.

### Argo CD

Argo CD는 쿠버네티스를 위한 GitOps 기반 지속적 배포(CD) 도구로, Git 저장소에 선언된 상태와 실제 클러스터 상태를 지속적으로 동기화한다.

**왜 필요한가** — 배포 과정을 자동화하고 Git을 단일 진실 공급원(single source of truth)으로 삼아 배포 이력을 추적하고 롤백을 쉽게 하기 위해 사용한다.

**발표에서는** — IDP의 배포 자동화 구성요소로서 GitOps 흐름의 예시로 언급되었다.

## 🧭 추구 방향과 흐름

- **Platform as a Product** — 플랫폼 팀이 인프라를 단순히 운영하는 것을 넘어, 개발자를 고객으로 삼아 제품을 만들듯 IDP를 설계하고 개선하는 방향으로 나아가고 있다. 이는 사용성, 문서화, 피드백 루프를 중시하는 접근으로 이어진다.
- **셀프서비스와 골든 패스** — 개발자가 티켓을 발행하고 기다리는 대신 표준화된 템플릿과 워크플로우(golden path)를 통해 스스로 리소스를 프로비저닝하고 배포할 수 있도록 하는 흐름이 확산되고 있다.
- **쿠버네티스 API 중심의 인프라 관리** — Crossplane처럼 클라우드 리소스를 쿠버네티스 커스텀 리소스로 다루는 접근이 늘어나면서, 애플리케이션과 인프라를 동일한 API와 GitOps 파이프라인으로 관리하는 흐름이 강화되고 있다.
- **개발자 경험(Developer Experience) 중심 설계** — IDP 관련 논의는 도구 나열을 넘어 개발자가 실제로 얼마나 빠르고 쉽게 작업을 완료할 수 있는지를 성공 지표로 삼는 방향으로 이동하고 있다.

## 🚀 바로 활용하기

1. Backstage 공식 문서를 따라 로컬 환경에 개발자 포털을 설치해보고 서비스 카탈로그를 만들어본다.
2. Crossplane을 쿠버네티스 클러스터에 설치하고 간단한 Composition으로 클라우드 리소스를 프로비저닝해본다.
3. Argo CD를 설치해 Git 저장소와 쿠버네티스 클러스터를 동기화하는 GitOps 흐름을 직접 구성해본다.
4. CNCF의 Platform Engineering 관련 자료를 읽고 조직에 맞는 골든 패스를 설계해본다.
