## 오늘의 기술 토픽

> **GitOps**

GitOps는 Git 저장소를 애플리케이션과 인프라의 단일 진실 공급원(source of truth)으로 삼아 배포와 운영을 자동화하는 접근 방식입니다. 선언적 설정 파일을 Git에 커밋하면 클러스터 상태가 자동으로 동기화되어 수동 배포로 인한 실수와 드리프트를 줄일 수 있습니다. Argo CD, Flux 같은 컨트롤러가 Git과 클러스터 상태를 지속적으로 비교하며 동기화를 담당하고, Kustomize나 Helm으로 매니페스트를 관리합니다. 최근에는 Crossplane 같은 도구로 애플리케이션뿐 아니라 인프라 리소스까지 GitOps 방식으로 확장하는 흐름도 나타나고 있습니다.

## 🔑 핵심 요점

- GitOps는 Git 저장소를 단일 진실 공급원으로 삼아 배포 상태를 관리하는 운영 철학입니다.
- 선언적 설정과 자동 동기화 덕분에 수동 kubectl apply로 인한 설정 드리프트를 방지할 수 있습니다.
- Argo CD와 Flux는 GitOps를 구현하는 대표적인 컨트롤러이며 둘 다 CNCF 프로젝트입니다.
- Kustomize와 Helm은 환경별로 매니페스트를 관리하고 템플릿화하는 데 함께 쓰입니다.
- Crossplane을 활용하면 애플리케이션뿐 아니라 클라우드 인프라 리소스도 GitOps 워크플로에 포함시킬 수 있습니다.
- GitOps는 배포 이력을 Git 커밋 로그로 남기기 때문에 감사(audit)와 롤백이 쉬워집니다.

## 🛠 핵심 기술 쉽게 이해하기

### GitOps

GitOps는 Git 저장소에 저장된 선언적 설정 파일을 기준으로 시스템 상태를 자동으로 맞춰나가는 운영 방식입니다. 개발자는 인프라나 애플리케이션 설정 변경을 코드 리뷰와 동일하게 Pull Request로 처리합니다.

**왜 필요한가** — 수동 배포 명령어 실행으로 발생하는 실수와 클러스터 상태가 문서와 어긋나는 드리프트 문제를 해결하기 위해 사용합니다.

**발표에서는** — 전체 브리핑의 핵심 주제로, GitOps가 무엇이고 왜 필요한지에 대한 기본 개념을 다룹니다.

### Argo CD

Argo CD는 쿠버네티스 환경에서 Git 저장소의 매니페스트와 실제 클러스터 상태를 지속적으로 비교하고 동기화해주는 GitOps 컨트롤러입니다. 웹 UI를 통해 배포 상태와 차이를 시각적으로 확인할 수 있습니다.

**왜 필요한가** — GitOps 원칙을 쿠버네티스 클러스터에 실제로 적용할 수 있게 해주는 대표적인 도구입니다.

**발표에서는** — GitOps를 구현하는 실전 도구로 언급되었습니다.

### Flux

Flux는 Argo CD와 함께 널리 쓰이는 또 다른 GitOps 컨트롤러로, Git 저장소 변경을 감지해 쿠버네티스 클러스터에 자동으로 반영합니다. CNCF의 GitOps Toolkit을 기반으로 모듈화된 구조를 가지고 있습니다.

**왜 필요한가** — Argo CD의 대안 또는 상호 보완적 선택지로, 경량화되고 확장 가능한 GitOps 파이프라인을 구성할 때 사용합니다.

**발표에서는** — GitOps 생태계의 대표적인 두 축 중 하나로 함께 언급되었습니다.

### Crossplane

Crossplane은 쿠버네티스 API를 확장해 클라우드 인프라 리소스(데이터베이스, 네트워크 등)를 쿠버네티스 커스텀 리소스처럼 선언적으로 정의하고 관리할 수 있게 해주는 도구입니다.

**왜 필요한가** — 애플리케이션뿐 아니라 인프라 프로비저닝까지 GitOps 워크플로 안에 통합하기 위해 사용합니다.

**발표에서는** — GitOps 범위를 애플리케이션에서 인프라 영역까지 넓히는 확장 사례로 소개되었습니다.

## 🧭 추구 방향과 흐름

- **인프라까지 아우르는 GitOps 확장** — 기존 GitOps가 애플리케이션 배포에 집중했다면, Crossplane 같은 도구를 통해 클라우드 인프라 프로비저닝까지 Git 기반 워크플로로 통합하려는 흐름이 커지고 있습니다.
- **플랫폼 엔지니어링과 셀프서비스** — GitOps는 개발자가 Pull Request만으로 배포와 인프라 변경을 요청할 수 있게 해, 플랫폼 팀이 셀프서비스 환경을 구축하는 기반이 되고 있습니다.
- **감사 가능성과 재현성 강화** — 모든 변경 이력이 Git 커밋으로 남기 때문에 배포 감사, 컴플라이언스, 장애 시 롤백이 용이해지는 방향으로 발전하고 있습니다.
