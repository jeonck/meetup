## 오늘의 기술 토픽

> **GitOps**

이 글은 Kubernetes 환경에서 배포와 운영을 코드로 관리하는 GitOps 방식을 소개한다. Git 저장소를 단일 진실 소스(Single Source of Truth)로 두고, Argo CD나 Flux CD 같은 컨트롤러가 클러스터 상태를 저장소 내용과 지속적으로 동기화하는 흐름을 다룬다. 수동 kubectl apply 대신 선언적 매니페스트와 자동 동기화로 배포 신뢰성과 추적성을 높이는 것이 핵심이다. 함께 자주 쓰이는 Kustomize, Helm 같은 매니페스트 관리 도구도 함께 살펴본다.

## 🔑 핵심 요점

- GitOps는 Git 저장소의 선언적 매니페스트를 클러스터의 실제 상태와 지속적으로 동기화하는 운영 방식이다.
- 배포 이력이 Git 커밋 로그로 남기 때문에 변경 추적과 롤백이 쉬워진다.
- Argo CD와 Flux CD는 GitOps를 구현하는 대표적인 Kubernetes 컨트롤러다.
- Kustomize와 Helm은 환경별 매니페스트를 관리하는 데 널리 쓰이는 보조 도구다.
- GitOps는 CI(빌드/테스트)와 CD(배포)를 분리해 배포 파이프라인의 보안성과 감사 가능성을 높인다.
- 선언적 접근 덕분에 클러스터 드리프트(설정 불일치)를 자동으로 감지하고 교정할 수 있다.

## 🛠 핵심 기술 쉽게 이해하기

### GitOps

GitOps는 애플리케이션과 인프라의 원하는 상태를 Git 저장소에 선언적으로 기술하고, 자동화 도구가 이를 실제 시스템 상태와 계속 맞춰주는 운영 방법론이다. 배포 명령을 직접 실행하는 대신 저장소에 변경을 커밋하면 시스템이 자동으로 반영된다.

**왜 필요한가** — 수동 배포로 인한 설정 불일치와 배포 이력 추적의 어려움을 해결하기 위해 사용한다.

**발표에서는** — 전체 글의 핵심 개념으로, 이후 소개되는 도구들이 이 방식을 어떻게 구현하는지의 기반이 된다.

### Argo CD

Argo CD는 Kubernetes용 GitOps 컨트롤러로, 지정한 Git 저장소의 매니페스트와 클러스터 상태를 비교하고 차이가 있으면 자동 또는 수동으로 동기화해준다. 웹 UI에서 애플리케이션 상태를 시각적으로 확인할 수 있다.

**왜 필요한가** — 여러 애플리케이션과 클러스터의 배포 상태를 한곳에서 선언적으로 관리하기 위해 쓴다.

**발표에서는** — GitOps를 실제로 구현하는 대표 도구로 언급된다.

### Flux CD

Flux CD는 CNCF 프로젝트로, Argo CD와 유사하게 Git 저장소를 소스로 삼아 Kubernetes 리소스를 자동 동기화하는 GitOps 툴킷이다. 경량화된 컨트롤러 구조와 확장 가능한 컴포넌트 모델이 특징이다.

**왜 필요한가** — GitOps 파이프라인을 더 모듈화되고 자동화된 방식으로 구성하고 싶을 때 사용한다.

**발표에서는** — Argo CD와 함께 GitOps 생태계의 또 다른 대표 구현체로 다뤄진다.

### Kustomize

Kustomize는 Kubernetes 매니페스트를 환경별로 오버레이해서 커스터마이징할 수 있게 해주는 템플릿 없는 관리 도구다. base와 overlay 구조로 dev/staging/prod 설정 차이를 관리한다.

**왜 필요한가** — 동일한 애플리케이션을 여러 환경에 맞게 반복 없이 배포하기 위해 사용한다.

**발표에서는** — GitOps 저장소 구조를 설계할 때 함께 사용되는 보조 도구로 소개된다.

## 🧭 추구 방향과 흐름

- **선언적 배포의 표준화** — 명령형 배포(kubectl apply, 스크립트 실행)에서 선언적 배포로 전환하는 흐름이 이어지고 있다. Git을 단일 진실 소스로 삼음으로써 배포 상태를 코드처럼 리뷰하고 버전 관리할 수 있게 된다.
- **지속적 동기화와 드리프트 감지** — Argo CD, Flux CD 같은 컨트롤러가 클러스터 상태를 계속 감시하며 저장소와의 불일치(드리프트)를 자동으로 감지하고 복구하는 방향으로 발전하고 있다.
- **보안 및 감사 가능성 강화** — CI와 CD를 분리해 배포 권한을 클러스터 내부 컨트롤러에 위임함으로써, 외부 시스템에 클러스터 자격 증명을 노출하지 않는 방향으로 나아가고 있다.

## 🚀 바로 활용하기

1. kind나 minikube로 로컬 Kubernetes 클러스터를 만들고 Argo CD를 설치해 샘플 애플리케이션을 동기화해본다.
2. Argo CD 공식 Getting Started 가이드를 따라 Git 저장소와 클러스터를 연결해본다.
3. Kustomize로 base/overlay 구조를 만들어 dev·prod 환경 매니페스트를 분리 관리해본다.
4. Flux CD 튜토리얼을 진행하며 Argo CD와의 구조적 차이를 비교해본다.
