## 오늘의 기술 토픽

> **eBPF Networking**

이번 글은 커널 레벨에서 네트워크 패킷과 시스템 콜을 가로채 처리할 수 있게 해주는 eBPF 기술을 중심으로, 이를 실제 프로덕션에 적용한 Cilium, Hubble, Tetragon 생태계를 정리한다. iptables 기반의 전통적인 Kubernetes 네트워킹이 가진 성능·가시성 한계를 eBPF가 어떻게 해결하는지, 그리고 이 흐름이 서비스 메시와 보안 영역까지 확장되는 방향을 다룬다. 입문자가 바로 따라할 수 있는 학습 경로도 함께 제시한다.

## 🔑 핵심 요점

- eBPF는 커널을 재컴파일하거나 커널 모듈을 올리지 않고도 커널 내부에서 코드를 안전하게 실행시키는 기술이다.
- Kubernetes에서는 iptables 기반 kube-proxy 대신 eBPF로 서비스 라우팅을 처리해 성능과 확장성을 개선하는 흐름이 자리잡고 있다.
- Cilium은 eBPF를 활용한 대표적인 CNI(Container Network Interface) 플러그인으로, 네트워킹과 보안 정책을 커널 레벨에서 처리한다.
- Hubble은 Cilium 위에서 동작하며 eBPF로 수집한 데이터를 기반으로 네트워크 흐름을 실시간으로 시각화해준다.
- Tetragon은 eBPF 기반으로 프로세스 실행, 파일 접근 같은 시스템 이벤트를 실시간 탐지하는 런타임 보안 도구다.
- eBPF 생태계는 네트워킹을 넘어 관측성(observability)과 보안을 하나의 데이터 소스로 통합하는 방향으로 확장되고 있다.

## 🛠 핵심 기술 쉽게 이해하기

### eBPF

eBPF(extended Berkeley Packet Filter)는 Linux 커널 안에서 샌드박스화된 프로그램을 안전하게 실행할 수 있게 해주는 기술이다. 커널 소스를 수정하거나 커널 모듈을 로드하지 않고도 네트워크 패킷, 시스템 콜, 함수 호출 등을 가로채 처리할 수 있다.

**왜 필요한가** — 기존에는 커널 동작을 바꾸려면 커널 모듈을 만들거나 커널 자체를 수정해야 했는데, eBPF는 이를 안전하고 동적으로 가능하게 해 성능과 유연성을 동시에 얻을 수 있다.

**발표에서는** — Kubernetes 네트워킹의 기반 기술로 소개되며, iptables 방식보다 어떻게 더 효율적으로 패킷을 처리하는지의 핵심 원리로 다뤄졌다.

### Cilium

Cilium은 eBPF를 기반으로 동작하는 Kubernetes CNI(네트워크 플러그인)로, 파드 간 네트워킹, 로드밸런싱, 네트워크 정책(방화벽) 기능을 커널 레벨에서 처리한다.

**왜 필요한가** — iptables 기반 네트워킹이 클러스터 규모가 커질수록 느려지고 디버깅이 어려운 문제를 해결하기 위해, eBPF로 더 빠르고 확장 가능한 네트워킹을 제공한다.

**발표에서는** — eBPF를 실제 프로덕션에 적용한 대표 사례로 다뤄지며, kube-proxy를 대체하는 방식과 네트워크 정책 적용 방식이 설명되었다.

### Hubble

Hubble은 Cilium에 내장된 관측성(observability) 도구로, 클러스터 내부의 네트워크 흐름과 서비스 간 통신을 실시간으로 시각화해준다.

**왜 필요한가** — eBPF로 수집한 저수준 네트워크 데이터를 사람이 이해할 수 있는 형태로 보여줘, 트러블슈팅과 트래픽 분석을 쉽게 해준다.

**발표에서는** — Cilium의 네트워크 가시성 기능을 보여주는 도구로 함께 언급되었다.

### Tetragon

Tetragon은 eBPF 기반의 런타임 보안 및 관측 도구로, 프로세스 실행, 파일 접근, 네트워크 연결 같은 시스템 이벤트를 커널 레벨에서 실시간으로 탐지한다.

**왜 필요한가** — 애플리케이션 레벨 로그만으로는 잡기 어려운 비정상 행위(침해, 권한 상승 시도 등)를 커널 이벤트 단위로 포착하기 위해 사용한다.

**발표에서는** — eBPF가 네트워킹을 넘어 보안 영역까지 확장되는 사례로 함께 소개되었다.

## 🧭 추구 방향과 흐름

- **kube-proxy에서 eBPF 기반 데이터플레인으로 전환** — iptables 체인이 길어질수록 성능이 저하되는 문제를 해결하기 위해 Cilium 같은 eBPF 기반 CNI가 kube-proxy를 대체하는 방향으로 발전하고 있다. 이는 대규모 클러스터에서 네트워킹 성능과 확장성을 동시에 확보하려는 움직임이다.
- **사이드카 없는(sidecar-less) 서비스 메시** — eBPF를 활용해 서비스 메시 기능(트래픽 라우팅, mTLS 등)을 사이드카 프록시 없이 커널 레벨에서 처리하려는 흐름이 생겨나고 있다. 이는 사이드카가 유발하는 리소스 오버헤드와 운영 복잡도를 줄이려는 목적이다.
- **관측성과 보안의 통합** — Hubble과 Tetragon처럼 동일한 eBPF 데이터 소스를 네트워크 가시성과 런타임 보안 탐지에 함께 활용하는 흐름이 강화되고 있다. 하나의 커널 레벨 데이터 파이프라인으로 여러 운영 요구를 충족시키려는 방향이다.

## 🚀 바로 활용하기

1. 로컬에 kind나 minikube로 Kubernetes 클러스터를 띄우고 Cilium을 CNI로 설치해본다.
2. cilium-cli로 클러스터 연결 상태를 확인하고 Hubble UI를 활성화해 실제 트래픽 흐름을 시각적으로 관찰해본다.
3. ebpf.io의 입문 가이드를 읽고 bpftool로 현재 시스템에 로드된 eBPF 프로그램을 직접 조회해본다.
4. Tetragon을 설치해 특정 프로세스 실행이나 파일 접근 이벤트가 실시간으로 어떻게 탐지되는지 테스트해본다.
