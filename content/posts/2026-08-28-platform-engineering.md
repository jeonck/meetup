## 오늘의 기술 토픽

> **Platform Engineering**

이번 자료는 특정 밋업 발표가 아니라 Platform Engineering이라는 주제를 중심으로 정리한 기술 브리프이다. 개발자가 인프라를 직접 다루지 않고도 애플리케이션을 배포하고 운영할 수 있도록 돕는 내부 개발자 플랫폼(IDP)의 개념과 관련 생태계를 소개한다. Crossplane, Argo CD, Backstage 같은 도구들이 어떻게 이 흐름을 뒷받침하는지 설명하고, 셀프서비스와 플랫폼을 제품처럼 다루는 최근 트렌드를 정리한다.

## 🔑 핵심 요점

- Platform Engineering은 개발자 생산성을 높이기 위해 내부 개발자 플랫폼(IDP)을 구축하는 활동이다.
- 핵심 목표는 개발자가 인프라 세부사항을 몰라도 셀프서비스로 리소스를 만들고 배포할 수 있게 하는 것이다.
- Crossplane 같은 도구는 클라우드 리소스를 쿠버네티스 API 방식으로 선언적으로 관리할 수 있게 해준다.
- Argo CD는 GitOps 방식으로 애플리케이션 배포를 자동화하는 데 널리 쓰인다.
- Backstage는 개발자 포털을 만들어 여러 도구와 서비스 카탈로그를 한 곳에서 관리하게 해준다.
- 플랫폼을 하나의 제품처럼 취급하고 내부 개발자를 고객으로 대하는 관점이 이 생태계의 핵심 방향이다.

## 🛠 핵심 기술 쉽게 이해하기

### Platform Engineering

Platform Engineering은 개발자가 애플리케이션을 더 빠르고 안전하게 만들고 배포할 수 있도록 내부 플랫폼을 설계하고 운영하는 분야이다. 이 플랫폼은 보통 쿠버네티스, CI/CD, 모니터링 등의 도구를 조합해서 만들어진다.

**왜 필요한가** — 개발자마다 인프라 지식 수준이 다르고 반복적인 설정 작업이 많아지는 문제를 해결하기 위해 등장했다.

**발표에서는** — 이번 브리프의 중심 주제로, 이후 소개되는 도구들이 모두 이 개념을 구현하는 수단으로 다뤄진다.

### Crossplane

Crossplane은 쿠버네티스 API를 확장해서 클라우드 인프라(데이터베이스, 네트워크 등)를 쿠버네티스 리소스처럼 선언적으로 정의하고 관리할 수 있게 해주는 오픈소스 프로젝트이다.

**왜 필요한가** — 여러 클라우드 제공자의 리소스를 하나의 통일된 방식으로 관리하고, 개발자에게 셀프서비스 API를 제공하기 위해 사용한다.

**발표에서는** — IDP 구성 요소 중 하나로, 개발자가 직접 클라우드 콘솔을 조작하지 않고도 인프라를 요청할 수 있게 하는 사례로 언급된다.

### Argo CD

Argo CD는 Git 저장소에 정의된 상태를 쿠버네티스 클러스터에 자동으로 동기화하는 GitOps 기반의 지속적 배포 도구이다.

**왜 필요한가** — 배포 과정을 Git 커밋 기록으로 추적 가능하게 만들고, 수동 배포로 인한 실수를 줄이기 위해 사용한다.

**발표에서는** — 플랫폼에서 애플리케이션 배포 파이프라인을 담당하는 핵심 구성 요소로 소개된다.

### Backstage

Backstage는 Spotify가 만든 오픈소스 개발자 포털 프레임워크로, 여러 서비스와 도구를 하나의 카탈로그와 UI로 통합해 보여준다.

**왜 필요한가** — 조직 내 서비스가 많아질수록 어떤 서비스가 어디 있고 누가 관리하는지 파악하기 어려워지는 문제를 해결한다.

**발표에서는** — 개발자에게 셀프서비스 경험을 제공하는 플랫폼 UI 계층의 대표 사례로 언급된다.

## 🧭 추구 방향과 흐름

- **플랫폼을 제품처럼 다루기** — 플랫폼 팀이 내부 개발자를 고객처럼 대하고, 실제 사용자 피드백을 반영해 플랫폼을 지속적으로 개선하는 방향이다. 이는 단순히 인프라를 관리하는 것을 넘어 사용성과 개발자 경험(DX)을 중시하는 흐름으로 이어진다.
- **셀프서비스와 표준화** — 개발자가 티켓이나 승인 없이도 표준화된 방식으로 리소스를 프로비저닝할 수 있게 만드는 것이 목표이다. Crossplane 같은 도구로 이런 셀프서비스 API를 쿠버네티스 네이티브 방식으로 구현하는 사례가 늘고 있다.
- **GitOps 기반 운영 확산** — 배포와 인프라 변경을 모두 Git을 단일 진실 공급원(source of truth)으로 관리하는 GitOps 방식이 플랫폼 엔지니어링의 표준 운영 모델로 자리잡고 있다.

## 🚀 바로 활용하기

1. Platform Engineering의 개념과 사례를 다루는 platformengineering.org 사이트를 읽어본다.
2. 로컬 쿠버네티스 클러스터(kind, minikube 등)에 Crossplane을 설치하고 간단한 리소스 정의를 만들어본다.
3. Argo CD 공식 문서의 Getting Started 가이드를 따라 GitOps 배포를 직접 구성해본다.
4. Backstage를 로컬에 띄워 서비스 카탈로그 기능을 체험해본다.
