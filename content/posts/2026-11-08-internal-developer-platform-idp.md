## 오늘의 기술 토픽

> **Internal Developer Platform (IDP)**

Internal Developer Platform(IDP)은 조직 내 개발자들이 인프라와 배포 과정을 직접 신경 쓰지 않고도 셀프서비스로 애플리케이션을 만들고 운영할 수 있게 해주는 내부 플랫폼이다. 쿠버네티스 도입 이후 늘어난 인프라 복잡도를 개발자에게 그대로 떠넘기지 않기 위해, 플랫폼 엔지니어링 팀이 표준화된 도구와 워크플로를 제공하는 방식으로 IDP가 주목받고 있다. Backstage 같은 개발자 포털, Crossplane 같은 인프라 추상화 도구, Argo CD 같은 GitOps 배포 도구가 IDP 구축의 핵심 축을 이룬다. 이 브리프는 IDP가 왜 필요한지, 그리고 함께 자주 쓰이는 관련 기술들을 정리한다.

## 🔑 핵심 요점

- IDP는 개발자가 인프라 세부사항을 몰라도 셀프서비스로 배포·운영할 수 있게 하는 내부 플랫폼이다.
- 쿠버네티스가 표준이 되면서 오히려 운영 복잡도가 커졌고, 이를 완화하기 위한 추상화 계층으로 IDP가 등장했다.
- Backstage는 여러 인프라 도구와 문서를 한 곳에서 보여주는 개발자 포털 역할을 한다.
- Crossplane은 클라우드 리소스를 쿠버네티스 API처럼 선언적으로 관리할 수 있게 해준다.
- Argo CD는 Git 저장소의 상태를 소스 오브 트루스로 삼아 배포를 자동화하는 GitOps 도구다.
- 플랫폼팀은 '황금 경로(golden path)'를 제공해 팀마다 다른 방식으로 인프라를 다루는 것을 막는다.
- IDP는 단순 도구 모음이 아니라 플랫폼을 하나의 제품처럼 설계하고 운영하는 접근 방식이다.

## 🛠 핵심 기술 쉽게 이해하기

### Internal Developer Platform (IDP)

IDP는 CI/CD, 쿠버네티스, 클라우드 리소스 같은 인프라를 추상화해서 개발자에게 셀프서비스 인터페이스로 제공하는 내부 플랫폼이다. 개발자는 복잡한 YAML이나 클라우드 콘솔을 직접 다루지 않고, 포털이나 CLI를 통해 필요한 리소스를 요청한다.

**왜 필요한가** — 쿠버네티스와 클라우드 네이티브 도구가 늘어나면서 개발자 1명이 알아야 할 운영 지식이 급격히 늘었고, 이를 플랫폼팀이 표준화해 흡수하기 위해 IDP를 구축한다.

**발표에서는** — 이번 브리프의 중심 주제로, IDP가 왜 필요한지와 이를 구성하는 대표 도구들을 함께 다룬다.

### Backstage

Backstage는 Spotify가 오픈소스로 공개한 개발자 포털 프레임워크로, 서비스 카탈로그, 문서, 템플릿을 한 화면에서 관리할 수 있게 해준다.

**왜 필요한가** — 조직 내 서비스와 소유자, 배포 상태가 흩어져 있을 때 이를 한곳에서 검색하고 표준 템플릿으로 새 서비스를 만들 수 있게 해준다.

**발표에서는** — IDP를 구성하는 대표적인 개발자 포털 도구로 언급된다.

### Crossplane

Crossplane은 쿠버네티스 API를 확장해 AWS, GCP, Azure 같은 클라우드 리소스를 쿠버네티스 커스텀 리소스(CR)로 선언하고 관리할 수 있게 해주는 오픈소스 프로젝트다.

**왜 필요한가** — 클라우드별 콘솔이나 Terraform 상태 파일을 따로 관리하지 않고, 쿠버네티스 하나의 컨트롤 플레인으로 인프라를 통합 관리하기 위해 쓴다.

**발표에서는** — IDP에서 인프라 추상화 계층을 담당하는 도구로 함께 소개된다.

### Argo CD

Argo CD는 Git 저장소에 정의된 선언적 매니페스트를 쿠버네티스 클러스터 상태와 지속적으로 동기화하는 GitOps 기반 배포 도구다.

**왜 필요한가** — 수동 배포나 임의 변경으로 인한 환경 불일치를 막고, Git 커밋 하나로 배포 전체를 추적·롤백할 수 있게 한다.

**발표에서는** — IDP의 배포 자동화 축으로, Crossplane·Backstage와 함께 전체 플랫폼 워크플로를 완성하는 도구로 다뤄진다.

## 🧭 추구 방향과 흐름

- **플랫폼을 제품처럼 다루기 (Platform as a Product)** — 플랫폼팀이 내부 개발자를 고객으로 보고, IDP를 지속적으로 개선되는 제품처럼 설계하는 흐름이다. Backstage 같은 포털로 사용자 경험을 신경 쓰는 것이 이 방향의 대표적 사례다.
- **인프라 셀프서비스화** — 개발자가 티켓을 넣고 기다리는 대신 플랫폼이 제공하는 템플릿과 API로 직접 리소스를 프로비저닝하는 방향으로 가고 있다. Crossplane 같은 선언적 API가 이를 기술적으로 뒷받침한다.
- **GitOps 기반 운영 표준화** — 배포와 인프라 변경을 모두 Git 커밋으로 추적하는 방식이 IDP의 기본 운영 모델로 자리 잡고 있다. Argo CD가 이 표준화의 핵심 축으로 다뤄진다.
- **황금 경로(Golden Path) 제공** — 모든 팀이 각자 다른 방식으로 배포·운영하지 않도록, 플랫폼팀이 미리 검증된 표준 경로를 제시하는 방향이다. 이는 플랫폼 복잡도를 줄이고 신규 개발자의 온보딩 속도를 높이는 것을 목표로 한다.

## 🚀 바로 활용하기

1. 로컬 환경에 Backstage를 npx로 설치해 기본 서비스 카탈로그와 템플릿 기능을 체험해본다.
2. 미니큐브나 kind로 로컬 쿠버네티스 클러스터를 띄우고 Crossplane을 설치해 간단한 provider로 리소스 하나를 선언적으로 생성해본다.
3. Argo CD 공식 문서의 Getting Started를 따라 Git 저장소와 클러스터를 동기화하는 기본 GitOps 흐름을 실습해본다.
4. platform engineering 개념을 다룬 CNCF 자료를 읽고, 자신의 조직에 맞는 IDP 범위(포털/인프라/배포 중 어디부터 시작할지)를 정리해본다.
