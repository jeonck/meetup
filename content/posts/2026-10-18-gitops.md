## 오늘의 기술 토픽

> **GitOps**

이번 글은 실제 밋업 발표 없이, GitOps라는 핵심 개념을 중심으로 관련 생태계를 정리한 테크 브리프입니다. GitOps는 Git 저장소를 단일 진실 공급원(Single Source of Truth)으로 삼아 애플리케이션과 인프라 상태를 선언적으로 관리하고 자동으로 동기화하는 운영 방식입니다. Argo CD, Flux 같은 컨트롤러가 Git의 선언적 정의를 클러스터 실제 상태와 지속적으로 비교·수렴시키며, Kustomize나 Helm 같은 템플릿 도구와 함께 쓰여 배포 파이프라인을 단순화합니다. 최근에는 보안 정책(Kyverno)과 결합해 배포뿐 아니라 거버넌스까지 Git 기반으로 통합하는 흐름이 강화되고 있습니다.

## 🔑 핵심 요점

- GitOps는 Git 저장소를 유일한 진실 공급원으로 삼아 배포 상태를 관리하는 방식이다.
- 사람이 직접 kubectl apply를 실행하는 대신, 컨트롤러가 Git과 클러스터 상태를 지속적으로 동기화한다.
- Argo CD와 Flux가 대표적인 GitOps 컨트롤러이며 CNCF 생태계에서 널리 쓰인다.
- Kustomize나 Helm 같은 템플릿 도구를 함께 사용해 환경별 설정 차이를 관리한다.
- 선언적 정책 도구(Kyverno)를 결합하면 배포 자동화와 보안 거버넌스를 같은 Git 흐름 안에서 처리할 수 있다.
- 변경 이력이 모두 Git 커밋으로 남기 때문에 롤백과 감사(audit)가 쉬워진다.

## 🛠 핵심 기술 쉽게 이해하기

### GitOps

GitOps는 애플리케이션과 인프라의 원하는 상태를 코드(YAML 등)로 작성해 Git 저장소에 저장하고, 이를 기준으로 실제 시스템 상태를 자동으로 맞춰주는 운영 패러다임입니다. 즉 'Git에 커밋하면 배포된다'는 흐름을 만드는 방식입니다.

**왜 필요한가** — 수동 배포로 인한 설정 불일치, 변경 이력 추적 어려움, 롤백의 복잡함 같은 문제를 해결하기 위해 등장했습니다.

**발표에서는** — 이번 브리프의 중심 주제로, 이후 소개되는 모든 도구가 이 개념을 구현하는 수단으로 다뤄집니다.

### Argo CD

Argo CD는 쿠버네티스 환경에서 GitOps를 구현하는 대표적인 지속적 배포(CD) 도구입니다. Git 저장소의 매니페스트와 클러스터의 실제 상태를 비교해 차이가 있으면 자동 또는 수동으로 동기화합니다.

**왜 필요한가** — 쿠버네티스 배포를 선언적이고 추적 가능하게 만들어 운영 신뢰성을 높이기 위해 사용합니다.

**발표에서는** — GitOps 생태계에서 가장 널리 쓰이는 구현체로 함께 언급됩니다.

### Flux

Flux는 Argo CD와 같은 목적을 가진 또 다른 GitOps 도구로, Git 저장소 변경을 감지해 쿠버네티스 클러스터에 자동 반영합니다. CNCF 프로젝트로 경량화된 구조가 특징입니다.

**왜 필요한가** — Argo CD와 비슷하게 선언적 배포 자동화를 제공하지만, 더 단순하고 확장 가능한 컨트롤러 구조를 선호하는 팀에서 선택됩니다.

**발표에서는** — GitOps를 구현하는 대안 도구로 Argo CD와 함께 비교 대상으로 언급됩니다.

### Kyverno

Kyverno는 쿠버네티스 네이티브 정책 엔진으로, YAML로 정책을 작성해 리소스 생성·수정 시 검증, 변경(mutation), 생성(generation)을 자동화합니다.

**왜 필요한가** — GitOps 흐름 안에서 보안 및 거버넌스 규칙까지 선언적으로 관리하기 위해 결합됩니다.

**발표에서는** — GitOps 배포 흐름에 정책 기반 거버넌스를 더하는 최근 트렌드의 예시로 다뤄집니다.

## 🧭 추구 방향과 흐름

- **선언적 운영(Declarative Everything)** — 인프라, 애플리케이션 배포, 보안 정책까지 모두 선언적 코드로 정의하고 Git으로 관리하는 흐름이 강화되고 있습니다. 명령형 스크립트 대신 '원하는 상태'를 기술하는 방식이 표준이 되어가고 있습니다.
- **Self-Service 플랫폼화** — GitOps 컨트롤러가 사람의 수동 개입을 줄이면서, 개발자는 Git PR만으로 배포를 요청하고 플랫폼 팀이 정의한 규칙(Kyverno 등) 안에서 자동 승인·거부되는 셀프서비스 모델로 이동하고 있습니다.
- **보안과 배포의 통합 (Policy as Code)** — Kyverno와 같은 정책 엔진이 GitOps 파이프라인에 결합되면서, 배포 자동화와 컴플라이언스 검증이 분리된 단계가 아니라 같은 Git 워크플로우 안에서 동시에 처리되는 방향으로 발전하고 있습니다.

## 🚀 바로 활용하기

1. 로컬 쿠버네티스 클러스터(kind, minikube 등)에 Argo CD를 설치하고 샘플 Git 저장소를 연결해 자동 동기화를 직접 체험해보기.
2. Argo CD 공식 문서의 'Getting Started' 가이드를 따라 첫 Application 리소스를 작성해보기.
3. Kustomize로 환경별(dev/staging/prod) 매니페스트 오버레이를 구성해보고 GitOps 저장소 구조를 설계해보기.
4. 간단한 Kyverno 정책(예: 특정 라벨 필수화)을 작성해 GitOps 배포 흐름에 적용해보기.
