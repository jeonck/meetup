## 오늘의 기술 토픽

> **Platform Engineering**

이번 브리핑은 최근 클라우드 네이티브 생태계에서 주목받는 Platform Engineering을 다룬다. 개별 서비스 배포마다 Kubernetes, CI/CD, 보안 정책을 직접 다뤄야 했던 개발자들의 피로를 줄이기 위해, 플랫폼 팀이 셀프서비스 형태의 내부 개발자 플랫폼(IDP)을 제품처럼 만들어 제공하는 흐름을 소개한다. Backstage 같은 개발자 포털, Crossplane 같은 인프라 추상화 도구, GitOps 기반의 Argo CD가 함께 묶여 '골든 패스(golden path)'를 구성하는 사례가 핵심이다. 궁극적으로는 개발자가 인프라 세부사항을 몰라도 빠르고 안전하게 서비스를 배포할 수 있도록 돕는 것이 목표다.

## 🔑 핵심 요점

- Platform Engineering은 개발자가 반복적으로 겪는 인프라 복잡성을 플랫폼 팀이 제품처럼 설계해 줄이는 접근이다.
- 핵심 산출물은 '셀프서비스'로, 개발자가 티켓 없이 스스로 환경을 프로비저닝할 수 있게 한다.
- Backstage 같은 개발자 포털은 여러 도구와 문서를 하나의 창구로 모아 온보딩 비용을 낮춘다.
- Crossplane은 Kubernetes API로 클라우드 리소스를 선언적으로 관리해 인프라를 애플리케이션처럼 다룰 수 있게 한다.
- Argo CD 기반 GitOps는 배포 상태를 코드로 관리해 플랫폼의 일관성과 감사 가능성을 높인다.
- 이 모든 요소는 '골든 패스'라는 표준화된 배포 경로로 수렴되어 신규 서비스 생성 시간을 단축한다.

## 🛠 핵심 기술 쉽게 이해하기

### Platform Engineering

소프트웨어 개발 과정에서 반복되는 인프라 설정, 배포, 모니터링 작업을 플랫폼 팀이 표준화된 도구와 워크플로우로 제공하는 분야다. 개발자는 복잡한 인프라 지식 없이도 셀프서비스로 필요한 리소스를 얻을 수 있다.

**왜 필요한가** — 각 팀이 Kubernetes, 네트워크, 보안 설정을 매번 처음부터 익히는 비효율을 줄이고 개발자 경험(DX)을 개선하기 위해 등장했다.

**발표에서는** — 전체 브리핑의 핵심 주제로, 왜 조직이 플랫폼을 '제품'처럼 다뤄야 하는지에 대한 배경으로 다뤄졌다.

### Backstage

Spotify가 만든 오픈소스 개발자 포털 프레임워크로, 서비스 카탈로그, 문서, 템플릿을 한 곳에서 관리할 수 있게 해준다.

**왜 필요한가** — 조직 내 흩어진 서비스 정보와 도구를 통합해 개발자가 필요한 것을 빠르게 찾고 새 서비스를 쉽게 생성하도록 돕는다.

**발표에서는** — 플랫폼의 사용자 접점(UI) 역할을 하는 대표적인 도구로 언급됐다.

### Crossplane

Kubernetes API를 확장해 클라우드 인프라(데이터베이스, 네트워크 등)를 쿠버네티스 커스텀 리소스처럼 선언적으로 정의하고 관리하는 오픈소스 도구다.

**왜 필요한가** — 여러 클라우드 제공자의 리소스를 하나의 일관된 API와 YAML로 다룰 수 있어 인프라 추상화와 자동화에 유리하다.

**발표에서는** — 플랫폼이 제공하는 셀프서비스 인프라 프로비저닝의 기반 기술로 소개됐다.

### Argo CD

GitOps 방식으로 Kubernetes 애플리케이션의 배포 상태를 Git 저장소와 동기화해주는 지속적 배포(CD) 도구다.

**왜 필요한가** — 배포 변경 이력을 Git으로 추적하고, 선언된 상태와 실제 클러스터 상태의 drift를 자동으로 감지·복구할 수 있다.

**발표에서는** — 플랫폼의 배포 파이프라인을 표준화하는 골든 패스의 한 축으로 다뤄졌다.

## 🧭 추구 방향과 흐름

- **플랫폼을 제품으로(Platform as a Product)** — 플랫폼 팀이 내부 개발자를 고객으로 보고, 사용성과 피드백을 반영해 플랫폼을 지속적으로 개선하는 방향이다. 단순 인프라 제공을 넘어 '제품 관리' 관점이 강조됐다.
- **셀프서비스와 골든 패스** — 개발자가 승인 대기 없이 표준화된 템플릿으로 서비스를 만들고 배포할 수 있는 길을 제공하는 흐름이다. Backstage 템플릿과 Crossplane, Argo CD 조합이 그 실현 수단으로 제시됐다.
- **개발자 경험(DX) 중심 설계** — 인프라 복잡성을 숨기고 개발자가 비즈니스 로직에만 집중하도록 하는 것이 플랫폼 성공의 척도로 다뤄졌다.

## 🚀 바로 활용하기

1. platformengineering.org에서 Platform Engineering의 정의와 성숙도 모델을 읽어본다.
2. 로컬 Kubernetes 클러스터(minikube 등)에 Backstage를 설치해 서비스 카탈로그를 만들어본다.
3. Crossplane 공식 문서의 Getting Started를 따라 간단한 클라우드 리소스를 선언적으로 생성해본다.
4. Argo CD를 설치해 Git 저장소와 연동한 뒤 간단한 애플리케이션을 GitOps 방식으로 배포해본다.
