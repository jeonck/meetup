## 오늘의 기술 토픽

> **GitOps**

이번 글은 실제 밋업 발표 없이 GitOps라는 주제를 중심으로 정리한 기술 브리프다. GitOps는 Git 저장소를 단일 진실 소스로 삼아 애플리케이션과 인프라 상태를 선언적으로 관리하고, 변경 사항을 자동으로 클러스터에 동기화하는 방식이다. Argo CD, Flux 같은 도구가 이 패턴을 구현하는 대표적인 컨트롤러이며, Crossplane이나 Kyverno 같은 주변 생태계 도구와 결합해 인프라 프로비저닝과 정책 적용까지 확장되는 흐름을 함께 다룬다. 전체적으로 선언적 상태 관리와 자동 동기화를 통해 배포의 일관성과 감사 가능성을 높이는 방향을 설명한다.

## 🔑 핵심 요점

- GitOps는 Git 저장소의 선언적 매니페스트를 단일 진실 소스로 사용해 배포 상태를 관리하는 방식이다.
- Argo CD나 Flux 같은 컨트롤러가 Git과 클러스터 상태를 지속적으로 비교하며 자동으로 동기화한다.
- 모든 변경 이력이 Git 커밋으로 남기 때문에 배포 추적과 롤백이 쉬워진다.
- Crossplane을 함께 쓰면 애플리케이션뿐 아니라 클라우드 인프라 리소스도 같은 GitOps 흐름으로 관리할 수 있다.
- Kyverno 같은 정책 엔진을 더하면 GitOps 파이프라인에 정책 검증 단계를 자연스럽게 통합할 수 있다.
- GitOps는 수동 kubectl apply를 줄이고 운영자의 실수를 줄이는 것을 목표로 한다.

## 🛠 핵심 기술 쉽게 이해하기

### GitOps

GitOps는 애플리케이션과 인프라의 원하는 상태를 Git 저장소에 선언적 파일(YAML 등)로 저장하고, 별도의 컨트롤러가 이를 실제 클러스터 상태와 지속적으로 비교해 일치시키는 운영 방식이다. 즉 Git에 커밋만 하면 배포가 자동으로 반영된다.

**왜 필요한가** — 수동 배포 작업으로 인한 환경 불일치와 변경 이력 추적의 어려움을 해결하기 위해 등장했다.

**발표에서는** — 이 글 전체의 중심 주제로, Git을 단일 진실 소스로 삼는 원칙과 자동 동기화 개념을 중심으로 다룬다.

### Argo CD

Argo CD는 Kubernetes 환경에서 GitOps를 구현하는 대표적인 컨티뉴어스 딜리버리 도구로, Git 저장소의 매니페스트와 클러스터 상태를 비교해 차이가 있으면 자동 또는 수동으로 동기화해준다.

**왜 필요한가** — GitOps 원칙을 실제로 클러스터에 적용할 수 있는 구체적인 컨트롤러가 필요하기 때문이다.

**발표에서는** — GitOps를 실현하는 가장 널리 쓰이는 도구 중 하나로 소개된다.

### Flux

Flux는 Argo CD와 비슷하게 Git 저장소를 기반으로 Kubernetes 클러스터 상태를 자동 동기화하는 CNCF GitOps 도구로, 더 가볍고 모듈식 구조를 가진다.

**왜 필요한가** — Argo CD의 대안으로 더 세밀한 컴포넌트 조합과 확장성을 원하는 팀을 위해 쓰인다.

**발표에서는** — GitOps 생태계의 또 다른 주요 선택지로 언급된다.

### Crossplane

Crossplane은 Kubernetes API를 확장해 클라우드 인프라 리소스(DB, 네트워크 등)까지 선언적으로 관리할 수 있게 해주는 오픈소스 프로젝트다.

**왜 필요한가** — 애플리케이션뿐 아니라 인프라까지 하나의 GitOps 워크플로우로 관리하려는 수요 때문이다.

**발표에서는** — GitOps 범위를 애플리케이션에서 인프라까지 넓히는 예시로 함께 다뤄진다.

### Kyverno

Kyverno는 Kubernetes 네이티브 정책 엔진으로, YAML 기반 정책을 통해 리소스 생성 시 검증·변형·생성 규칙을 적용할 수 있다.

**왜 필요한가** — GitOps 파이프라인에 정책 검증 단계를 추가해 잘못된 변경이 자동 반영되는 것을 막기 위해서다.

**발표에서는** — GitOps와 결합해 정책 기반 거버넌스를 적용하는 흐름의 예로 언급된다.

## 🧭 추구 방향과 흐름

- **선언적 인프라 관리의 확장** — GitOps가 애플리케이션 배포를 넘어 Crossplane을 통한 클라우드 인프라 프로비저닝까지 확장되는 흐름이 나타난다. 이는 애플리케이션과 인프라를 동일한 Git 기반 워크플로우로 통합 관리하려는 지향점을 보여준다.
- **정책 기반 거버넌스 통합** — Kyverno 같은 정책 엔진을 GitOps 파이프라인에 결합해 배포 전후 검증을 자동화하는 방향이 강조된다. 이를 통해 수동 검토 없이도 보안·규정 준수 요건을 지속적으로 강제할 수 있다.
- **플랫폼 엔지니어링으로의 발전** — GitOps는 개발자가 직접 인프라를 다루지 않고 Git 커밋만으로 변경을 요청하는 셀프서비스 플랫폼의 기반 기술로 자리잡고 있다. Argo CD·Flux 같은 컨트롤러가 그 중심 구성요소로 다뤄진다.

## 🚀 바로 활용하기

1. 로컬 Kubernetes 클러스터(kind, minikube 등)에 Argo CD를 설치하고 샘플 Git 저장소를 연결해 자동 동기화를 직접 체험해본다.
2. Flux 공식 문서의 Get Started 가이드를 따라 Argo CD와 비교해보며 두 도구의 차이를 이해한다.
3. Crossplane 공식 문서를 통해 Kubernetes 리소스로 클라우드 인프라를 선언하는 예제를 실습한다.
4. Kyverno의 기본 정책 예제를 적용해 GitOps 파이프라인에 간단한 검증 규칙을 추가해본다.
