## 오늘의 기술 토픽

> **GitOps**

이번 글은 특정 밋업 발표가 아닌, GitOps라는 주제를 중심으로 정리한 기술 브리프입니다. GitOps는 Git 저장소를 단일 진실 공급원(single source of truth)으로 삼아 인프라와 애플리케이션 상태를 선언적으로 관리하는 방법론입니다. Argo CD, Flux 같은 도구가 Git의 상태를 지속적으로 클러스터와 동기화하면서, 배포 자동화와 변경 추적성을 동시에 확보합니다. 아래에서는 GitOps와 밀접하게 연결되는 주변 기술들, 그리고 생태계가 나아가는 방향을 함께 살펴봅니다.

## 🔑 핵심 요점

- GitOps는 Git 커밋을 변경의 유일한 트리거로 삼아 인프라와 앱 배포를 관리하는 방식입니다.
- Argo CD나 Flux 같은 컨트롤러가 Git 저장소와 클러스터 상태를 지속적으로 비교하고 동기화합니다.
- 선언적 설정을 쓰기 때문에 배포 이력이 Git 커밋 로그로 그대로 남아 추적과 롤백이 쉬워집니다.
- Kustomize나 Helm 같은 템플릿 도구와 함께 쓰여 환경별 설정 차이를 관리합니다.
- Kubernetes 생태계에서 GitOps는 CI와 CD를 분리하는 표준적인 접근으로 자리잡고 있습니다.
- 정책 자동화 도구와 결합하면 배포 전후 검증까지 파이프라인에 포함시킬 수 있습니다.

## 🛠 핵심 기술 쉽게 이해하기

### GitOps

GitOps는 애플리케이션과 인프라의 원하는 상태(desired state)를 Git 저장소에 선언적으로 기술하고, 자동화된 컨트롤러가 실제 클러스터 상태를 그 선언과 일치시키는 운영 방식입니다. 변경이 필요하면 코드를 수정하듯 Git에 커밋하고 Pull Request를 올리는 것이 유일한 변경 경로가 됩니다.

**왜 필요한가** — 수동 배포로 인한 설정 드리프트와 '누가 무엇을 언제 바꿨는지' 추적이 어려운 문제를 해결하기 위해 사용합니다.

**발표에서는** — 이번 브리프의 중심 주제로, Git을 단일 진실 공급원으로 쓰는 개념 자체를 핵심적으로 다룹니다.

### Argo CD

Argo CD는 Kubernetes용 GitOps 컨티뉴어스 딜리버리 도구로, Git 저장소의 매니페스트를 지속적으로 감시하면서 클러스터 상태와 비교하고 차이가 있으면 자동 또는 수동으로 동기화합니다. 웹 UI를 통해 배포 상태를 시각적으로 확인할 수 있습니다.

**왜 필요한가** — 수동 kubectl apply 대신 선언적이고 추적 가능한 방식으로 Kubernetes 배포를 자동화하기 위해 사용합니다.

**발표에서는** — GitOps를 실제로 구현하는 대표적인 도구로 소개되는 맥락에서 다뤄집니다.

### Flux

Flux는 Argo CD와 유사하게 CNCF 산하의 GitOps 툴킷으로, Git 저장소 변경을 감지해 Kubernetes 클러스터에 자동으로 반영합니다. 모듈화된 컨트롤러 구조로 이미지 업데이트 자동화 같은 기능도 제공합니다.

**왜 필요한가** — Argo CD와 함께 GitOps 구현의 양대 축으로, 조직의 요구에 따라 선택적으로 사용됩니다.

**발표에서는** — GitOps 생태계의 대표 도구 중 하나로 비교 대상으로 언급되는 맥락에서 다뤄집니다.

### Kustomize

Kustomize는 Kubernetes 매니페스트를 템플릿 엔진 없이 오버레이(overlay) 방식으로 환경별로 커스터마이징할 수 있게 해주는 도구입니다. 베이스 설정에 패치를 얹어 dev/staging/prod 등 환경 차이를 관리합니다.

**왜 필요한가** — GitOps 저장소에서 환경별 설정 중복을 줄이고 유지보수를 쉽게 하기 위해 사용합니다.

**발표에서는** — GitOps 워크플로우에서 매니페스트 관리 도구로 함께 언급되는 보조 기술로 다뤄집니다.

## 🧭 추구 방향과 흐름

- **선언적 운영(Declarative Operations)으로의 전환** — GitOps는 명령형(imperative) 스크립트 실행 대신 '원하는 상태'를 선언하고 컨트롤러가 이를 지속적으로 수렴시키는 방식을 지향합니다. 이는 Kubernetes의 컨트롤러 패턴을 운영 영역까지 확장한 흐름으로, 생태계 전체가 선언적 접근을 표준으로 받아들이는 방향으로 가고 있습니다.
- **감사 가능성과 보안 강화** — 모든 변경이 Git 커밋과 Pull Request를 통해 이루어지기 때문에, 누가 무엇을 바꿨는지에 대한 완전한 감사 추적(audit trail)이 자연스럽게 생깁니다. 클러스터에 직접 접근 권한을 주지 않고 Git 권한만 관리하면 되므로 보안 경계를 좁히는 방향으로도 이어집니다.

## 🚀 바로 활용하기

1. 로컬 Kubernetes 클러스터(kind 또는 minikube)에 Argo CD를 설치하고 샘플 저장소를 연결해 자동 동기화를 체험해보세요.
2. 간단한 Kubernetes 매니페스트 저장소를 만들고 Kustomize로 dev/prod 오버레이를 구성해보세요.
3. Argo CD 공식 문서의 'Getting Started' 가이드를 따라 첫 Application 리소스를 배포해보세요.
4. Git 커밋 하나로 배포 상태가 바뀌는 과정을 직접 실행해 보며 GitOps의 선언적 동기화 흐름을 눈으로 확인해보세요.
