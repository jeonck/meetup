## 오늘의 기술 토픽

> **AI Agents for Operations (AIOps)**

AIOps는 장애 탐지, 원인 분석, 복구 작업처럼 반복적이고 많은 데이터를 다뤄야 하는 운영(Operations) 업무를 AI 에이전트가 대신 수행하도록 하는 접근 방식이다. 기존 모니터링 도구가 수집한 지표와 로그를 LLM 기반 에이전트가 해석해 이상 징후를 설명하고, 필요한 조치를 제안하거나 직접 실행하는 흐름으로 발전하고 있다. 클라우드 네이티브 생태계에서는 Kubernetes 클러스터 운영에 특화된 에이전트 프레임워크들이 등장하면서, 사람이 매번 대시보드를 보고 판단하던 작업을 에이전트가 1차로 처리하는 방향으로 옮겨가는 중이다.

## 🔑 핵심 요점

- AIOps는 운영팀의 반복 작업(탐지-분석-대응)을 AI 에이전트가 대신 수행하게 하는 흐름을 말한다.
- 에이전트가 제대로 동작하려면 Prometheus, OpenTelemetry 같은 양질의 관측 데이터가 먼저 갖춰져 있어야 한다.
- Kubernetes 운영에 특화된 에이전트 프레임워크(예: kagent)는 클러스터 상태를 자연어로 질의하고 조치까지 제안하는 것을 목표로 한다.
- 완전 자율 실행보다는 사람이 최종 승인하는 휴먼인더루프 구조가 현재 실무에서 더 선호된다.
- AIOps 도입은 거대한 플랫폼 전환이 아니라 기존 모니터링 스택에 에이전트 레이어를 얹는 점진적 작업으로 시작하는 것이 현실적이다.

## 🛠 핵심 기술 쉽게 이해하기

### AI Agents for Operations (AIOps)

AIOps는 시스템 로그, 메트릭, 이벤트 같은 운영 데이터를 AI가 분석해서 장애를 예측하거나 원인을 찾아내고, 필요한 조치를 제안·실행하도록 하는 개념이다. 전통적인 규칙 기반 알림 시스템과 달리 LLM을 활용해 맥락을 이해하고 사람처럼 설명하는 데 초점이 있다.

**왜 필요한가** — 운영팀이 매번 수많은 알림과 대시보드를 직접 뒤지며 원인을 찾는 데 드는 시간과 피로도를 줄이기 위해 쓴다.

**발표에서는** — 운영 업무 전반을 AI 에이전트에게 위임한다는 상위 주제로 소개되며, 이후 등장하는 관측성 도구와 에이전트 프레임워크가 이를 구현하는 구체적 수단으로 다뤄진다.

### kagent

kagent는 Kubernetes 클러스터를 대상으로 동작하는 AI 에이전트 프레임워크로, 클러스터 상태를 자연어로 질의하거나 문제 진단, 조치 제안을 자동화하는 것을 목표로 한다.

**왜 필요한가** — Kubernetes 운영은 리소스, 네트워크, 권한 등 변수가 많아 사람이 수동으로 확인하기 번거로운데, 이를 에이전트가 자동으로 조사하고 요약하게 하기 위해 쓴다.

**발표에서는** — AIOps를 Kubernetes 환경에 적용하는 구체적 구현체로 언급되어, 운영 에이전트가 실제 클러스터와 어떻게 상호작용하는지를 보여주는 예시로 다뤄진다.

### Prometheus

Prometheus는 시스템과 애플리케이션의 메트릭을 주기적으로 수집하고 저장하는 오픈소스 모니터링 도구로, 클라우드 네이티브 환경의 표준 관측성 스택으로 널리 쓰인다.

**왜 필요한가** — AI 에이전트가 판단을 내리기 위한 원재료인 메트릭 데이터를 안정적으로 쌓아두기 위해 필요하다.

**발표에서는** — AIOps 에이전트가 분석할 데이터 소스로서 기반 인프라 역할로 언급된다.

### OpenTelemetry

OpenTelemetry는 로그, 메트릭, 트레이스 같은 관측 데이터를 수집하는 방식을 표준화한 오픈소스 프로젝트로, 다양한 모니터링 백엔드에 동일한 형식으로 데이터를 보낼 수 있게 해준다.

**왜 필요한가** — 에이전트가 여러 시스템에서 나오는 데이터를 일관된 형태로 받아 분석할 수 있게 하기 위해 쓴다.

**발표에서는** — AIOps 에이전트가 신뢰할 수 있는 입력 데이터를 확보하는 표준화 계층으로 함께 언급된다.

## 🧭 추구 방향과 흐름

- **관측성에서 자율 대응으로의 확장** — 기존에는 Prometheus, OpenTelemetry로 데이터를 모으고 사람이 대시보드를 보며 판단했지만, 이제는 그 위에 AI 에이전트를 얹어 분석과 1차 대응까지 맡기는 방향으로 나아가고 있다. 관측 데이터의 품질이 에이전트 판단의 신뢰도를 좌우한다는 점이 함께 강조된다.
- **휴먼인더루프 거버넌스** — 에이전트가 모든 조치를 자동 실행하기보다, 진단과 제안까지만 하고 실제 실행은 사람이 승인하는 구조가 현재 실무에 적합하다는 방향이 드러난다. 이는 운영 실수를 자동화가 오히려 증폭시킬 위험을 통제하기 위한 선택이다.
- **Kubernetes 생태계 중심의 에이전트 도구화** — kagent처럼 Kubernetes를 대상으로 한 전용 에이전트 프레임워크가 등장하면서, AIOps가 범용 개념에서 특정 플랫폼에 특화된 실행 도구로 구체화되는 흐름이 보인다.

## 🚀 바로 활용하기

1. Prometheus와 Grafana로 기본 모니터링 스택을 먼저 구축해 메트릭 데이터를 확보한다.
2. OpenTelemetry 공식 문서를 보고 애플리케이션에 표준화된 계측(instrumentation)을 적용해본다.
3. kagent 같은 Kubernetes 전용 AI 에이전트 프로젝트의 문서를 읽고 테스트 클러스터에서 간단한 질의부터 시도해본다.
4. 에이전트가 제안한 조치를 바로 실행하지 말고 사람이 검증하는 휴먼인더루프 워크플로를 먼저 설계해본다.
