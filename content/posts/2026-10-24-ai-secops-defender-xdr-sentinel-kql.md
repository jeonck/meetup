## 📋 밋업 한눈에 보기

이 세션은 클라우드와 AI 에이전트 환경에서의 위협 지형을 짚고, Microsoft Entra·Defender·Purview·Sentinel이 어떻게 통합 SecOps 체계를 구성하는지 설명했다. 이어서 KQL을 활용한 가설 기반 위협 헌팅 쿼리 패턴을 다루고, 마지막으로 Agent 365 관점에서 AI 에이전트의 신원·권한·격리·관측 가능성을 수명주기 전반에서 어떻게 보호해야 하는지 소개했다. 전체적으로 ID 중심 공격 대응과 AI 에이전트 고유의 새로운 공격 경로 방어를 함께 다룬 세션이다.

## 🔑 핵심 요점

- 클라우드 보안 사고의 주된 원인은 여전히 비밀번호 스프레이, 피싱, 토큰/세션 도용 같은 ID 중심 공격이다.
- AI 에이전트는 프롬프트 인젝션, 민감 정보 유출, 과도한 권한, 악성 도구 호출, 취약한 플러그인·공급망 같은 새로운 위협에 노출된다.
- Microsoft Entra, Defender for Cloud/Cloud Apps, Purview가 결합해 통합 텔레메트리와 정책 경계를 제공한다.
- Defender XDR은 엔드포인트·ID·이메일·SaaS 알림을 연결해 공격 시나리오(Incident) 단위로 추적한다.
- Microsoft Sentinel은 다양한 로그를 ASIM으로 정규화하고 분석 규칙·플레이북으로 자동 대응과 위협 헌팅을 수행한다.
- Sentinel의 Azure 포털 지원은 2027년 3월 31일 이후 종료되며 Defender 포털로 통합 전환이 진행 중이다.
- AI 에이전트 보안은 설계 단계의 위협 모델링부터 배포 후 가드레일, 레드팀 테스트, 관측 가능성 확보까지 수명주기 전체를 관리해야 한다.

## 🛠 핵심 기술 쉽게 이해하기

### Microsoft Defender XDR

엔드포인트, ID, 이메일, SaaS 애플리케이션 등 여러 영역에서 발생하는 보안 알림과 엔티티를 하나로 연결해 보여주는 통합 탐지·대응 플랫폼이다. 개별 알림을 따로 보는 대신 공격의 전체 흐름을 하나의 사건(Incident)으로 모아서 파악할 수 있게 해준다.

**왜 필요한가** — 서로 다른 시스템에서 발생한 알림을 사람이 수동으로 연결하는 데는 시간이 오래 걸리고 놓치기 쉬운데, 이를 자동으로 교차 상관분석해 조사 시간을 줄이기 위해 사용한다.

**발표에서는** — 엔드포인트·ID·이메일·SaaS 간 알림과 엔티티를 연결해 공격 시나리오를 추적하는 핵심 조사 도구로 소개됐다.

### Microsoft Sentinel

클라우드 기반 SIEM(보안 정보 이벤트 관리) 서비스로, 다양한 소스에서 로그를 모아 정규화한 뒤 분석 규칙과 플레이북을 통해 위협을 탐지하고 대응을 자동화한다.

**왜 필요한가** — 조직 전체의 로그를 한 곳에 모아 일관된 형식(ASIM)으로 분석해야 규칙 기반 탐지와 자동화된 대응, 그리고 체계적인 위협 헌팅이 가능하기 때문이다.

**발표에서는** — ASIM을 통한 로그 정규화, 분석 규칙/플레이북 기반 자동 대응이 설명됐고, Azure 포털 지원이 2027년 3월 31일 종료되며 Defender 포털로 통합된다는 전환 일정이 공유됐다.

### KQL (Kusto Query Language)

로그와 이벤트 데이터를 질의하는 쿼리 언어로, Sentinel과 Defender의 Advanced Hunting에서 데이터를 검색·분석할 때 사용된다.

**왜 필요한가** — 방대한 로그에서 로그인 실패/성공 패턴, 새로운 IP 조합, 영속성 시도 같은 특정 징후를 가설 기반으로 빠르게 찾아내기 위해 필요하다.

**발표에서는** — 로그인 패턴 분석, 새로운 서비스 프롬프트/IP 페어 탐지, schtasks.exe 등 엔드포인트 영속성 조사, Defender-Sentinel 간 ID 상관관계 분석 등 구체적인 쿼리 패턴이 제시됐다.

### Microsoft Entra

사용자와 시스템의 신원(ID)을 관리하고 인증·권한을 제어하는 ID 플랫폼이다.

**왜 필요한가** — ID 중심 공격이 클라우드 보안 사고의 주원인이기 때문에, 신원 보호가 보안 체계의 출발점이 된다.

**발표에서는** — Defender for Cloud/Cloud Apps, Purview와 결합해 통합 텔레메트리와 정책 경계를 구성하는 요소로 언급됐다.

### Microsoft Purview

조직의 데이터를 분류하고 보호하기 위한 데이터 거버넌스·보호 서비스다.

**왜 필요한가** — AI 에이전트가 민감 정보에 접근·유출할 위험이 커지는 상황에서 데이터 수준의 보호 정책이 필요하기 때문이다.

**발표에서는** — Entra, Defender와 함께 통합 보안 체계를 이루는 데이터 보호 축으로 소개됐다.

### Agent 365

AI 에이전트의 신원 소유, 권한 범위, 데이터 접근, 모델/오케스트레이션 경계, 도구·런타임 격리를 설계하기 위한 Microsoft의 에이전트 보안 패턴/프레임워크다.

**왜 필요한가** — AI 에이전트가 사람처럼 행동하지만 전통적인 ID·권한 모델로는 통제하기 어려운 새로운 위협 표면을 만들기 때문에, 에이전트 전용 보안 설계 원칙이 필요하다.

**발표에서는** — 명확한 신원 소유자, 범위가 지정된 권한, 승인된 데이터 검색, 모델/오케스트레이션 경계, 툴·런타임 격리, 모니터링/복구 체계라는 보안 설계 패턴으로 제시됐고, 위협 모델링부터 배포 후 가드레일·레드팀 테스트·관측 가능성 확보까지 수명주기 관리가 강조됐다.

## 🧭 추구 방향과 흐름

- **ID 중심 보안(Identity-centric Security)** — 클라우드 보안 사고의 주원인이 여전히 비밀번호 스프레이, 피싱, 토큰 도용 같은 ID 공격이라는 점에서, Entra를 중심으로 신원 보호를 보안 체계의 기반으로 삼는 방향이 강조됐다.
- **SecOps 플랫폼 통합** — Defender XDR과 Sentinel을 하나의 포털로 통합하고, Azure 포털 기반 Sentinel 지원을 2027년 3월 종료하는 전환 계획에서 보듯, 여러 보안 도구를 단일 플랫폼으로 합쳐 운영 효율을 높이려는 방향이 뚜렷하다.
- **AI 에이전트 보안의 수명주기 관리** — 설계 단계의 위협 모델링, 배포 후 가드레일, 레드팀 테스트, 운영 중 관측 가능성까지 에이전트 보안을 전체 수명주기로 다루는 접근이 제시됐다. 이는 기존 애플리케이션 보안에 적용되던 shift-left 원칙을 AI 에이전트로 확장한 것이다.
- **가설 기반 위협 헌팅(Hypothesis-driven Hunting)** — KQL을 활용해 특정 공격 패턴(영속성, 비정상 로그인, 새로운 IP 조합 등)을 사전에 가정하고 능동적으로 탐색하는 헌팅 방식이 핵심 기법으로 다뤄졌다.

## 🚀 바로 활용하기

1. Microsoft Sentinel과 Defender XDR의 KQL Advanced Hunting 쿼리 예제를 직접 실행해 로그인 실패/성공 패턴과 영속성(schtasks.exe) 탐지를 연습해본다.
2. Agent 365에서 제시한 신원 소유자·권한 범위·도구 격리 패턴을 현재 사용 중인 AI 에이전트/챗봇 설계에 대조해 점검표로 만들어본다.
3. Azure 포털 기반 Sentinel을 사용 중이라면 2027년 3월 31일 지원 종료 전에 Defender 포털로의 전환 계획을 미리 검토한다.
4. ASIM 정규화 스키마 문서를 읽고 현재 수집 중인 로그 소스가 정규화 규칙에 맞게 들어오는지 확인한다.
